# Audit Keamanan dbpanel — Rencana 1 (Fondasi Panel dan Agent)

- Tanggal: 2026-10-30
- Commit yang diaudit: `82fe728` (HEAD, `fix(install): fetch both agent binaries online, drop cmp, document re-pairing`)
- Modul: `github.com/husmin-fajrin/db-panel`
- Sifat: audit internal atas kode milik sendiri, baca-saja terhadap repo; semua PoC dijalankan di direktori sementara dengan `--data-dir`/`--config-dir` sementara pada 127.0.0.1.

---

## 1. Ringkasan eksekutif

Tingkat risiko keseluruhan: **Sedang, dengan satu temuan Tinggi**. Dasar desainnya sehat: perintah agent berupa registry tetap, kueri SQL selalu berparameter, `html/template` meng-escape semua data dari agent (stored XSS lewat probe sudah dicoba dan gagal), mTLS memakai TLS 1.3 saja dengan identitas server yang terikat ke CN sertifikat, dan CSRF ditahan pemeriksaan Origin/Referer. Yang paling berat adalah **binary dirakit dengan Go 1.26.0**: `govulncheck` menemukan 36 kerentanan pustaka standar yang terjangkau dari kode, beberapa bisa dipicu tanpa autentikasi di :8080 dan :8443 (SEC-01). Sebelum dipakai di produksi, perbaiki minimal: SEC-01 (toolchain), SEC-03 (re-pairing tidak memutus koneksi lama), SEC-04 (sesi tidak dicabut saat reset sandi), SEC-05 (DoS login lewat rotasi IP), SEC-07 (verifikasi binary panel saat instalasi) dan SEC-08 (header keamanan). SEC-02 (pembajakan token pairing lewat `ps`) dan SEC-06 (panel berjalan sebagai root) wajib selesai sebelum Rencana 2 memberi agent kuasa admin MySQL.

## 2. Lingkup dan metode

**File yang dibaca seluruhnya:** `cmd/dbpanel/main.go`, `internal/version/version.go`, `internal/panel/{panel,cli,servers,listener_impl,localagent}.go`, `internal/panel/web/{router,handlers_auth,handlers_servers,render,sse}.go`, `internal/panel/auth/{middleware,password,ratelimit,session}.go`, `internal/panel/agentapi/{pair,install,ws,listener}.go`, `internal/panel/ca/ca.go`, `internal/panel/hub/{hub,conn_ws,conn_local}.go`, `internal/panel/store/{store,migrate,servers,tokens,users,settings}.go` + `migrations/0001_init.sql`, `internal/agent/{cli,pair,runtime,session}.go`, `internal/agent/config/config.go`, `internal/agent/commands/registry.go`, `internal/agent/probe/{probe,system}.go`, `internal/proto/{codec,messages,probe}.go`, `web/embed.go`, `web/templates/*.html`, `web/templates/agent-install.sh.tmpl`, `scripts/{install.sh,install_test.sh,vendor.sh,tailwind.sh}`, `scripts/systemd/*.service`, `Makefile`, `go.mod`, `go.sum`, `README.md`, `.gitignore`, spesifikasi (bagian 6, 7.1, 7.2, 9) dan Rencana 1. Berkas `*_test.go` ditelusuri untuk melihat apa yang sudah diuji (148 fungsi test).

**Alat yang dijalankan:**
- `make build`, `go test ./...` (semua lulus), `go mod verify` (semua modul cocok dengan go.sum), `go list -m all`.
- `govulncheck v1.9.0 -show verbose ./...` dengan `GOTOOLCHAIN=go1.26.0` (toolchain yang benar-benar dipakai untuk build) dan DB cermin `https://storage.googleapis.com/go-vulndb` (`vuln.go.dev` diblokir proxy lingkungan audit). Lihat Lampiran.

**PoC yang dicoba** (hasil di tiap temuan): pembajakan token dari argv, koneksi lama tetap hidup setelah re-pair, cookie lama tetap sah setelah `reset-password`, bypass rate limit per-IP dan DoS bcrypt, injeksi `$(...)` lewat `--public-host`, koneksi menggantung tanpa batas, banjir dan flapping agent, stored XSS lewat probe (gagal), CSRF lintas origin (ditolak), DNS rebinding terhadap pemeriksaan Origin, `safeNext` dengan 11 variasi open redirect (semua aman), TLS 1.2 dan tanpa sertifikat klien (ditolak), sertifikat CA sebagai klien (ditolak di aplikasi), kebijakan kunci CSR, izin berkas, directory listing, Range header besar.

## 3. Model ancaman

1. **Penyerang LAN tanpa autentikasi** yang menjangkau :8080 dan :8443 (termasuk lewat IPv6 link-local yang aktif di hampir semua host Linux).
2. **Penyerang on-path aktif** (ARP/DHCP spoofing) antara server DB dan panel, saat dan setelah instalasi.
3. **Operator terautentikasi** yang keliru, dan **orang dalam jahat** yang memegang sandi admin.
4. **Agent yang dibobol atau jahat** dengan sertifikat klien sah: dampaknya ke panel, baris server lain, browser operator, SQLite, dan ketersediaan.
5. **Host panel yang dibobol**: kuasa atas semua agent (root di semua server DB menurut desain).
6. **Penyerang lokal** di host panel atau host DB (izin berkas, argv proses, hardening systemd).
7. **Rantai pasok**: pin modul Go, aset JS/CSS vendor, skrip unduhan Tailwind/daisyUI, rilis GitHub tanpa tanda tangan.

### SEC-01 — Binary dirakit dengan Go 1.26.0: 36 kerentanan stdlib terjangkau
- **Tingkat:** Tinggi. **Dieksploitasi oleh:** LAN tanpa autentikasi (:8080, :8443), agent.
- **Lokasi:** `go.mod:3` (`go 1.26.0`, tanpa direktif `toolchain`), `Makefile:6`, `Makefile:11`.
- **Serangan dan dampak:** `go.mod` hanya menetapkan versi minimum. Di mesin yang Go lokalnya lebih tua dari 1.26 (di lingkungan audit 1.24.7), `go build` mengunduh **tepat** go1.26.0, sehingga `dist/dbpanel` dan rilis memakai stdlib tanpa tambalan 1.26.1–1.26.10. Yang relevan untuk deployment ini:
  - Pra-autentikasi di :8080: GO-2026-6609 (Range header tanpa batas di `FileServer`/`ServeContent`, CPU), GO-2026-6608 (bypass batas memori parsing header MIME), GO-2026-6218 (`net/url` kuadratik).
  - Pra-autentikasi di :8443: GO-2026-4947 (kerja tak terbatas saat membangun rantai sertifikat dari intermediate yang dikirim klien; verifikasi sertifikat klien berjalan sebelum CN diperiksa).
  - Agent terautentikasi: GO-2026-4870 (KeyUpdate TLS 1.3 menahan koneksi), beberapa bug HTTP/2 server (lihat SEC-20).
  - `html/template`: GO-2026-4980, -4982, -4865, -6091, -6599, -6600, -4603 (bypass escaper atau XSS). Template saat ini tidak memakai konteks yang terdampak (tidak ada aksi di dalam `<script>`, template literal JS, atau `<meta content>`), jadi belum bisa dieksploitasi, tetapi template Rencana 2+ akan tumbuh.
- **Bukti:**
  ```
  $ go version dist/dbpanel dist/dbpanel_linux_amd64
  dist/dbpanel: go1.26.0
  dist/dbpanel_linux_amd64: go1.26.0
  $ GOTOOLCHAIN=go1.26.0 govulncheck -db https://storage.googleapis.com/go-vulndb ./...
  Your code is affected by 36 vulnerabilities from the Go standard library.
  ```
  Amplifikasi Range pra-autentikasi pada `/static/app.css` (77 KB): 8000 rentang → respons 206 sebesar 1,17 MB dalam 0,48 s per permintaan (`curl -H @range.txt http://127.0.0.1:18080/static/app.css`). Catatan proses: `go run golang.org/x/vuln/cmd/govulncheck@latest ./...` **melaporkan 0 kerentanan** karena `go run` beralih ke toolchain go1.26.10 untuk menjalankan govulncheck; hasil itu menyesatkan.
- **Perbaikan minimal:** tambah `toolchain go1.26.10` (atau naikkan `go 1.26.10`) di `go.mod`, rakit ulang rilis, dan jalankan `GOTOOLCHAIN=<toolchain build> govulncheck ./...` di CI pada setiap rilis.
- **Kapan:** sebelum rilis.

### SEC-02 — Token pairing terbaca dari argv proses, pairing bisa dibajak pengguna lokal host DB
- **Tingkat:** Sedang. **Dieksploitasi oleh:** pengguna lokal tanpa hak istimewa di server DB saat instalasi agent; siapa pun yang melihat riwayat shell operator.
- **Lokasi:** `web/templates/agent-install.sh.tmpl:36` (token di URL argumen `curl`), `:67` (`--token "{{.Token}}"`), `internal/agent/cli.go:90`, `internal/panel/web/handlers_servers.go:146` (perintah `curl ...?token=...`), `internal/panel/web/handlers_servers.go:15` (TTL 24 jam).
- **Serangan dan dampak:** `/proc/<pid>/cmdline` proses root bisa dibaca semua pengguna (tanpa `hidepid`). Selama `curl` mengunduh binary (1–3 detik di LAN 100 Mbit), pengguna lokal mana pun bisa membaca token dan mengirim `POST /agent/pair` lebih dulu dengan CSR miliknya sendiri. Penyerang mendapat sertifikat `agent-<id>` untuk server itu; pemasang yang sah gagal dengan "token ditolak". Di Rencana 1 penyerang bisa memalsukan data probe; di Rencana 2 panel akan mengirim perintah dan **rahasia** (password user replikasi, kredensial bot Telegram lewat `notify.telegram.send`) ke identitas palsu itu. Token juga tertinggal di `~/.bash_history` operator dan berlaku 24 jam bila pairing gagal.
- **Bukti:**
  ```
  # sebagai nobody, melihat proses root:
  $ su -s /bin/bash nobody -c 'ps -eo user,args | grep -- --token'
  root  /usr/local/bin/dbpanel agent pair --panel http://10.0.0.1:8080 --token PC3JQ-XSD88-JSXHT 20
  # balapan nyata: pengamat membaca /proc/*/cmdline, pemasang menjalankan langkah skrip
  token sah db-tiga: NEQPD-RSE9T-FCTSA
  pengamat: token tertangkap dari argv curl: NEQPD-RSE9T-FCTSA
  pair: 4 127.0.0.1:18443 <nil>                 <- penyerang dapat sertifikat server #4
  pemasang: unduhan selesai
  pemasangan gagal: token ditolak oleh panel    <- pemasang sah gagal
  ```
- **Perbaikan minimal:** jangan pernah menaruh token di argv. Di skrip: kirim token lewat header dari stdin (`curl -H @- ... <<<"Authorization: Bearer $TOKEN"` atau `curl -K -`), dan berikan ke `dbpanel agent pair` lewat stdin atau variabel lingkungan (`DBPANEL_PAIR_TOKEN`; `/proc/<pid>/environ` hanya bisa dibaca pemiliknya). Di panel: perpendek TTL (mis. 1 jam), tampilkan di halaman server "dipasangkan dari IP X pada waktu Y", dan beri peringatan bila pairing berhasil dari IP yang berbeda dengan pengunduh skrip.
- **Kapan:** sebelum Rencana 2 (sebaiknya sebelum rilis).

### SEC-03 — Re-pairing tidak memutus koneksi agent dengan sertifikat lama
- **Tingkat:** Sedang. **Dieksploitasi oleh:** pemegang kunci agent lama (agent dibobol atau kunci bocor).
- **Lokasi:** `internal/panel/agentapi/pair.go:128` (`MarkPaired` tanpa `Hub.Disconnect`), `internal/panel/agentapi/ws.go:35` (serial hanya dicek saat upgrade), `internal/panel/hub/hub.go:63`; teks yang tidak akurat di `web/templates/server_detail.html:35`, `:119` dan `README.md:85-87`.
- **Serangan dan dampak:** "Pasang ulang agent" adalah satu-satunya cara operator mencabut sertifikat (misalnya saat kunci agent diduga bocor). Setelah pairing baru berhasil, koneksi WebSocket yang sudah terbuka dengan sertifikat lama **tetap** menjadi koneksi aktif, tampil Online, dan terus menerima perintah sampai agent baru tersambung. Kalau agent baru tidak pernah tersambung (server mati, firewall), koneksi penyerang bertahan tanpa batas waktu.
- **Bukti:** agent jahat `hold` tersambung dengan sertifikat lama → `POST /servers/2/token` → pairing baru sukses (`cert_serial=e6a7…`) pada 10:37:47 → halaman server tetap `x-data="{ online: true }"`, dan log agent lama memperlihatkan dua permintaan `probe` lagi (sekitar 10:38:45 dan 10:39:45). Sambungan ulang dengan sertifikat lama ditolak 403, jadi pemeriksaan hanya berlaku untuk koneksi baru.
- **Perbaikan minimal:** setelah `MarkPaired` sukses di `PairHandler`, panggil `d.Hub.Disconnect(pt.ServerID)` (atau simpan serial di `WSConn` dan putuskan koneksi yang serialnya bukan serial terbaru). Tambahkan test "re-pair memutus koneksi lama". Perbaiki teks UI/README.
- **Kapan:** sebelum rilis.

### SEC-04 — Sesi tidak dicabut saat `reset-password`; tanpa umur sesi absolut
- **Tingkat:** Sedang. **Dieksploitasi oleh:** penyerang yang memegang cookie sesi (dicuri lewat HTTP polos, perangkat bersama, atau orang dalam yang aksesnya dicabut).
- **Lokasi:** `internal/panel/cli.go:98-118` (reset hanya mengubah hash di DB), `internal/panel/auth/session.go:47-59` (TTL bergeser, tanpa batas absolut), `internal/panel/panel.go:40` (12 jam).
- **Serangan dan dampak:** sesi disimpan di memori proses panel, sedangkan `dbpanel panel reset-password` berjalan di proses lain dan tidak bisa mencabutnya. Respons insiden yang wajar ("reset sandi admin") tidak mengeluarkan penyerang. Karena kedaluwarsanya bergeser, penyerang yang membuat satu permintaan setiap <12 jam tetap masuk selamanya. Tidak ada "keluar dari semua sesi".
- **Bukti:**
  ```
  $ dbpanel panel reset-password --data-dir data --config-dir conf
  Kata sandi baru untuk admin: <disensor>
  $ curl -b cj http://127.0.0.1:18080/servers   -> 200, "Keluar (admin)"   (cookie lama)
  ```
- **Perbaikan minimal:** simpan "epoch kredensial" per pengguna di DB (dinaikkan oleh reset/ganti sandi); `Sessions.Create` mencatat epoch, dan `RequireLogin` menolak sesi yang epoch-nya kalah. Tambahkan umur absolut (mis. 12 jam sejak login) di samping batas idle (mis. 30–60 menit), plus tombol "keluar dari semua sesi".
- **Kapan:** sebelum rilis.

### SEC-05 — Rate limit login per-IP dilewati dengan rotasi IP; bcrypt tanpa batas konkurensi (DoS)
- **Tingkat:** Sedang. **Dieksploitasi oleh:** LAN tanpa autentikasi.
- **Lokasi:** `internal/panel/web/handlers_auth.go:46-63`, `internal/panel/auth/ratelimit.go:31-50`, `internal/panel/auth/password.go:32`.
- **Serangan dan dampak:** batasnya 5 percobaan per IP per 15 menit, tanpa batas global. Setiap percobaan menjalankan bcrypt cost 12 (~0,3 s CPU). Di LAN penyerang bisa memakai banyak alamat sumber: alias IPv4 yang tidak terpakai, atau tanpa batas lewat IPv6 link-local (`fe80::/64`, aktif secara default; `:8080` mendengarkan dual-stack). Hasilnya login admin tidak tersedia dan CPU panel jenuh (probe dan SSE ikut melambat). Map limiter juga tumbuh tanpa batas dan disapu O(n) di bawah mutex global pada setiap percobaan. Menebak sandi tetap tidak praktis karena sandi acak 16 karakter (~95 bit). Bila panel di balik reverse proxy, semua klien berbagi satu kunci `RemoteAddr`, sehingga satu orang bisa mengunci semua pengguna.
- **Bukti:**
  ```
  127.0.0.5 x6 -> 200 200 200 200 200 429 ; 127.0.0.6 -> 200 ; 127.0.0.7 -> 200
  baseline login 303 0.27s
  500 percobaan paralel dari 500 IP (127.10.a.b) -> login sah: 303 32.57s   (4 vCPU)
  ```
- **Perbaikan minimal:** semaphore global untuk bcrypt (mis. `NumCPU/2` slot, permintaan lain langsung 429), limiter global untuk kegagalan (mis. 30/menit) di samping per-IP, kunci IPv6 per /64, dan batas jumlah entri map.
- **Kapan:** sebelum rilis.

### SEC-06 — Panel web berjalan sebagai root tanpa hardening systemd; kunci CA di proses yang menghadap LAN
- **Tingkat:** Sedang. **Dieksploitasi oleh:** penyerang LAN yang punya bug eksekusi kode di lapisan HTTP/parsing (berantai, misalnya dengan SEC-01); penyerang lokal.
- **Lokasi:** `scripts/systemd/dbpanel-panel.service:7` (`User=root`), `scripts/install.sh:127-141`, `internal/panel/panel.go:148` (CA dimuat di proses web), `internal/panel/ca/ca.go:128`, `scripts/systemd/dbpanel-agent.service`.
- **Serangan dan dampak:** di Rencana 1 panel tidak butuh root: port 8080/8443 di atas 1024, dan probe tertanam hanya membaca `/etc/os-release` dan `/proc` serta menjalankan `systemctl is-active` dan `mysqld --version`. Meski begitu, proses HTTP yang menghadap LAN berjalan sebagai root tanpa `NoNewPrivileges`, `ProtectSystem`, `PrivateTmp`, dan seterusnya, dan memegang `ca.key` di memori. Bug eksekusi kode apa pun di panel langsung menjadi root di host panel, dan kunci CA bisa dipakai menerbitkan sertifikat server `dbpanel-panel` untuk menyamar sebagai panel ke semua agent (yang berjalan sebagai root).
- **Bukti:** isi unit file (hanya `ExecStart`, `Restart`, `User=root`); `systemd-analyze security` tidak dijalankan karena lingkungan audit tanpa systemd.
- **Perbaikan minimal (Rencana 1):** jalankan panel sebagai pengguna `dbpanel` dengan `StateDirectory=dbpanel`, `ConfigurationDirectory=dbpanel`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `PrivateDevices=yes`, `ProtectKernelTunables/Modules/Logs=yes`, `ProtectControlGroups=yes`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`, `RestrictNamespaces=yes`, `LockPersonality=yes`, `MemoryDenyWriteExecute=yes`, `SystemCallArchitectures=native`, `CapabilityBoundingSet=` (kosong), `UMask=0077`. Untuk Rencana 2: pisahkan agent tertanam menjadi service root tersendiri (bisa `dbpanel agent` biasa yang tersambung ke panel lewat mTLS di loopback), supaya proses web tetap tanpa hak istimewa. Agent memang harus root; hardening yang masih mungkin di sana (`ProtectKernelModules`, `ProtectClock`, `RestrictSUIDSGID`, `LockPersonality`, `SystemCallArchitectures=native`, `RestrictRealtime`) hanya kosmetik, karena agent bisa memerintah PID 1 lewat `systemctl`. Jadi batas sesungguhnya ada di registry perintah (SEC-22).
- **Kapan:** sebelum Rencana 2 (unit panel non-root sebaiknya sebelum rilis).

### SEC-07 — Rilis tanpa tanda tangan; binary panel utama tidak diverifikasi
- **Tingkat:** Sedang. **Dieksploitasi oleh:** rantai pasok (akun GitHub/rilis dibobol, cache/proxy jahat).
- **Lokasi:** `scripts/install.sh:48-50` (binary panel diunduh tanpa cek sama sekali), `:79-85` (agent dicek dengan `SHA256SUMS` dari origin yang sama, plus `--ignore-missing`), `scripts/install.sh:4` dan `README.md:17` (`curl .../main/scripts/install.sh | sudo bash` dari branch yang bisa berubah), `scripts/tailwind.sh:47,55` dan `scripts/vendor.sh:16` (alat build diunduh tanpa checksum yang dipin), spesifikasi bagian 10 ("agent diperbarui oleh panel").
- **Serangan dan dampak:** binary yang dijalankan sebagai root di host panel, lalu disebarkan ke semua server DB, hanya dilindungi HTTPS ke GitHub. `SHA256SUMS` dari rilis yang sama hanya melindungi dari unduhan rusak, bukan dari penerbit palsu. Binary panel bahkan tidak dicek terhadap `SHA256SUMS` walaupun berkas itu tersedia. `--ignore-missing` juga meloloskan berkas yang tidak tercantum. Tailwind CLI dan plugin daisyUI dieksekusi di mesin developer tanpa pin hash. README menyebut binary agent "diperiksa dengan SHA256SUMS", yang terdengar lebih kuat daripada kenyataannya. Alpine.js yang dikomit cocok dengan npm (lihat bagian 5).
- **Perbaikan minimal:** (1) verifikasi binary panel terhadap `SHA256SUMS` dan buang `--ignore-missing` (wajibkan dua baris yang diharapkan); (2) tandatangani `SHA256SUMS` dengan minisign/cosign dan sematkan kunci publiknya di `install.sh` dan di binary (untuk update agent kelak); (3) contoh di README memakai tag rilis, bukan `main`; (4) pin SHA-256 untuk Tailwind/daisyUI/Alpine di skrip build.
- **Kapan:** (1) dan (3) sebelum rilis; (2) sebelum Rencana 2 (sebelum ada fitur update otomatis); (4) nanti.

### SEC-08 — Header keamanan HTTP di bawah baseline
- **Tingkat:** Sedang (pertahanan berlapis untuk panel yang kelak memegang root di semua server DB; halaman berisi token pairing bisa disimpan di cache). **Dieksploitasi oleh:** LAN, terautentikasi.
- **Lokasi:** `internal/panel/web/router.go:80-87` (hanya `X-Frame-Options` dan CSP `frame-ancestors`), `internal/panel/web/router.go:100-106`, `internal/panel/agentapi/pair.go:159-163`, `internal/panel/agentapi/install.go:73-74,113-115`, `internal/panel/panel.go` (`uiHandler` tidak membungkus `/agent/*`).
- **Detail:** lihat bagian **5A Security headers** untuk tabel per kelas respons, perubahan yang dibutuhkan agar CSP ketat berjalan, dan potongan middleware.
- **Perbaikan minimal:** pasang middleware `securityHeaders` (bagian 5A) di atas seluruh mux UI (termasuk `/agent/*`), pindahkan skrip inline ke berkas statis, dan pakai build Alpine CSP.
- **Kapan:** header non-CSP sebelum rilis; CSP ketat sebelum Rencana 2.

### SEC-09 — Injeksi perintah shell lewat `--public-host` ke skrip pemasang yang berjalan sebagai root
- **Tingkat:** Rendah (sekarang hanya bisa diatur oleh root di host panel atau penulis `panel.db`; naik menjadi Tinggi begitu public host bisa diubah dari UI pengaturan). **Dieksploitasi oleh:** root lokal / penulis DB panel; admin bila kelak ada UI.
- **Lokasi:** `internal/panel/cli.go:73`, `internal/panel/panel.go:163-166` (disimpan permanen tanpa validasi), `internal/panel/agentapi/install.go:63` (`text/template`, tanpa quoting shell), `web/templates/agent-install.sh.tmpl:2,36,37,67,90`, `internal/panel/web/handlers_servers.go:146`.
- **Serangan dan dampak:** nilai host disisipkan apa adanya di dalam tanda kutip ganda bash, sehingga `$(...)` atau backtick dieksekusi sebagai root di setiap server DB yang menjalankan perintah pemasangan. Nilainya juga tersimpan di setelan `public_host` dan bertahan tanpa flag.
- **Bukti:**
  ```
  $ dbpanel panel ... --public-host '127.0.0.1$(id>/dev/stderr)'
  log: public_url=http://127.0.0.1$(id>/dev/stderr):28080
  skrip baris 67:  "$BIN" agent pair --panel "http://127.0.0.1$(id>/dev/stderr):28080" --token "N345A-709NS-VQ5V3"
  $ bash line.sh          (BIN diganti echo)
  uid=0(root) gid=0(root) groups=0(root)
  ```
- **Perbaikan minimal:** validasi saat parse dan saat dibaca dari DB: `net.ParseIP` atau hostname `^[A-Za-z0-9.-]{1,253}$`. Di template, ganti interpolasi dengan fungsi `shquote` (kutip tunggal dengan `'\''`), atau tulis nilai sebagai variabel di awal skrip, dengan kutip tunggal.
- **Kapan:** sebelum rilis (murah), wajib sebelum ada UI pengaturan.

### SEC-10 — Server HTTP tanpa ReadTimeout/IdleTimeout: koneksi menggantung tanpa batas
- **Tingkat:** Rendah. **Dieksploitasi oleh:** LAN tanpa autentikasi.
- **Lokasi:** `internal/panel/servers.go:99-103` (hanya `ReadHeaderTimeout`), `internal/panel/agentapi/listener.go:35-40`.
- **Serangan dan dampak:** body yang dikirim sangat lambat dan koneksi keep-alive yang menganggur tidak pernah diputus. Setiap koneksi memakan goroutine, buffer, dan satu fd; batas fd proses (`LimitNOFILE`) atau memori akhirnya menghentikan UI, pairing, dan listener agent karena keduanya berbagi tabel fd yang sama.
- **Bukti:** `python3 slow.py 75` → `idle keep-alive setelah 75s: MASIH TERBUKA`, `slow body setelah 75s: MASIH TERBUKA`, `header belum lengkap: DITUTUP server`. 19.990 koneksi body-lambat dari satu host: RSS panel naik dari 32 MB ke 178 MB (~7,3 KB/koneksi). Kehabisan fd tidak tercapai di lingkungan audit (batas 20.000 untuk klien PoC juga).
- **Perbaikan minimal:** `ReadTimeout: 30s`, `IdleTimeout: 120s`, `MaxHeaderBytes: 64<<10`, dengan `http.ResponseController.SetWriteDeadline/SetReadDeadline` untuk memperpanjang khusus `/events`; batasi koneksi per IP (mis. `netutil.LimitListener` plus penghitung per IP).
- **Kapan:** sebelum rilis.

### SEC-11 — Agent jahat bisa membanjiri log/DB dan menyimpan probe 4 MiB
- **Tingkat:** Rendah. **Dieksploitasi oleh:** agent (sertifikat sah).
- **Lokasi:** `internal/panel/hub/conn_ws.go:14` (`readLimit` 4 MiB), `:169-188`, `internal/panel/agentapi/ws.go:52-59` (log Warn/Info per koneksi), `internal/panel/listener_impl.go:23-31` (setiap attach = tulis DB + SSE + goroutine probe), `internal/proto/probe.go` (tanpa batas ukuran field), `internal/panel/store/servers.go:156`.

Jawaban probe hingga ~4 MiB disimpan di `probe_json`, dan setiap tampilan halaman server men-decode lalu merendernya. ### SEC-12 — Directory listing di `/static/`

### SEC-13 — Rahasia saat diam: token plaintext, `panel.db` 0644, sandi awal tidak dihapus
- **Tingkat:** Rendah. **Dieksploitasi oleh:** pengguna lokal di host panel, salinan backup.
- **Lokasi:** `internal/panel/panel.go:95` (`MkdirAll(…, 0o750)` tidak mengencangkan direktori yang sudah ada), `internal/panel/store/store.go:22-23` (SQLite membuat `panel.db`, `-wal`, `-shm` dengan 0644), `internal/panel/store/tokens.go:71,103` (token disimpan dan dicari sebagai plaintext), `internal/panel/panel.go:228-238` dan `scripts/install.sh:175-176` (sandi awal tetap tersimpan di `/etc/dbpanel/admin-initial-password` selamanya).

### SEC-14 — Header Host tidak divalidasi: DNS rebinding melewati pemeriksaan Origin
- **Tingkat:** Rendah. **Dieksploitasi oleh:** situs eksternal yang dibuka operator di browser yang ada di LAN rumah sakit.
- **Lokasi:** `internal/panel/web/handlers_auth.go:118-130` (membandingkan host Origin dengan `r.Host`, yang dikendalikan klien).
- **Serangan dan dampak:** halaman penyerang di `evil.example` me-rebind DNS ke IP panel. ### SEC-16 — Nama server tanpa batas panjang dan karakter

## 5. Yang diperiksa dan dinilai aman

- **SQL:** semua kueri berparameter (`internal/panel/store/*.go`); migrasi berjalan dalam transaksi (`migrate.go:56-69`). DSN dari flag root saja.
- **Escaping template:** `html/template` di semua halaman; payload XSS dari agent di semua field probe ter-escape (PoC SEC-11). `{{.Server.ID}}` di `x-init` adalah integer, `{{.Online}}` boolean. SSE hanya mengirim `{"id","online"}` dan tidak membawa string dari agent (`listener_impl.go:28`, `:93`).
- **Open redirect `safeNext`** (`handlers_auth.go:100-115`): `//evil.com`, `/\evil.com`, `/%5Cevil.com`, `/.//evil.com`, `%2F%2Fevil.com`, `https:evil.com`, `///evil.com`, `/..//evil.com`, `/%2e%2e//evil.com`, `/%09/evil.com` semuanya tetap di origin panel.
- **CSRF:** semua route POST (`/login`, `/logout`, `/servers`, `/servers/{id}/token`, `/servers/{id}/delete`) melewati `sameOrigin`; Origin asing, `null`, atau tanpa header → 403; Referer `127.0.0.1:18080.evil.example` → 403. Cookie `SameSite=Lax; HttpOnly`.
- **Sesi:** token 256 bit dari `crypto/rand` dan selalu baru saat login (tidak ada fiksasi); logout menghapus sesi di server; path `{id}` diparse `ParseInt` (negatif atau overflow → 404).
- **Enumerasi pengguna:** `dummyHash` adalah bcrypt cost 12 yang valid (dibandingkan dalam 0,30 s), jadi waktu respons pengguna tidak dikenal sama.
- **Token pairing:** 15 simbol Crockford dari `crypto/rand` tanpa bias (75 bit), sekali pakai lewat `UPDATE … WHERE used_at IS NULL AND expires_at > ?` yang atomik (tidak ada race), token lama dihapus saat token baru dibuat atau saat pairing; CSR diperiksa sebelum token dikonsumsi; token tidak pernah ditulis ke log; respons skrip dan binary `no-store`.
- **Endpoint binary:** `{arch}` di-allowlist (`amd64|arm64`), tidak ada path traversal; berkas non-regular ditolak; `os.Executable` dievaluasi `EvalSymlinks`.
- **CA/mTLS:** P-256, serial acak 128 bit; subjek dan SAN dari CSR diabaikan; leaf `IsCA=false`, EKU `clientAuth`; listener `RequireAndVerifyClientCert` dan TLS 1.3 saja (TLS 1.2 → alert 70, tanpa sertifikat → alert 116); sertifikat CA atau sertifikat server sebagai klien ditolak di aplikasi (`not an agent certificate`); agent memin CA panel dan `ServerName=dbpanel-panel`, dan sertifikat agent lain tidak bisa dipakai menyamar sebagai panel (tanpa SAN, EKU hanya client). Serial dicek terhadap DB pada setiap upgrade (sertifikat basi → 403). `ca.key` 0600 dibuat dengan `O_EXCL` di direktori 0700.
- **Hub:** respons dikorelasikan per koneksi dengan ID acak 128 bit, jadi agent tidak bisa menjawab permintaan agent lain; panel mengabaikan `request` dari agent; ping 10 s memutus peer mati; kompresi WebSocket nonaktif (default `coder/websocket` v1.8.15, tidak ada bom dekompresi); `Accept` memeriksa Origin.
- **Agent:** `agent.yaml`, kunci, dan sertifikat ditulis atomik 0600 di direktori 0700 lewat `CreateTemp` (aman dari symlink); `agent pair` menolak direktori milik panel; registry tidak mengeksekusi string dari panel; panic di handler ditangkap; perintah dibatasi `requestTimeout` 10 menit. `probe` hanya menjalankan `uname`, `systemctl is-active` dan `mysqld --version/--verbose --help` dengan argumen tetap; `mysqld` dicari di `PATH` systemd yang hanya bisa ditulis root (`probe.go:152,189`).
- **Proto:** `encoding/json` membatasi kedalaman nesting; ukuran pesan dibatasi `SetReadLimit` di kedua sisi; jenis envelope divalidasi.
- **Log:** slog TextHandler meng-quote newline dan ESC (diuji: `hostname="evil\ntime=… \x1b[31m"`), jadi injeksi log tidak mungkin; sandi dan kunci tidak pernah dicatat.
- **Skrip:** tidak ada `set -x` (diuji `install_test.sh`); berkas `.new` ada di `/usr/local/bin` milik root (tidak ada TOCTOU dari pengguna biasa); token Crockford aman disisipkan; `AGENT_TMP` dari `mktemp -d`.
- **Header:** tidak ada header `Server`; `X-Frame-Options: DENY` dan `frame-ancestors 'none'` di semua halaman UI.
- **Modul Go:** `go mod verify` → semua modul terverifikasi; `golang.org/x/crypto` v0.58.0 hanya terdampak advisory modul `openpgp` yang tidak dipakai. Alpine.js yang dikomit (`sha256 3ed1eed2…0ad3`) identik dengan `alpinejs-3.14.9.tgz` dari npm, dan integritas tarball `sha512-gqSOhT…AYlw==` cocok dengan registry.

### 5A. Security headers (kelas respons, dicek dengan `curl -i` ke binary yang berjalan)

Baseline: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: no-store` untuk halaman terautentikasi dan apa pun yang berisi token.

**Perubahan agar CSP ketat berjalan:**
1. Skrip inline `salinTeks` di `web/templates/layout.html:8-25` dipindah ke `web/static/app.js` dan dimuat dengan `<script defer src="/static/app.js">`.
2. Atribut `onclick` di `web/templates/server_detail.html:107` dan `:109` dibuang dan diganti listener di `app.js` (mis. `data-open-modal="modal-hapus"`) atau method komponen Alpine.

5. Sebagai langkah sementara yang lebih lemah sampai butir 3 selesai: `script-src 'self' 'unsafe-eval'` (setelah butir 1–2), tanpa `'unsafe-inline'`.

**Middleware yang direkomendasikan** (satu fungsi di `internal/panel/web/router.go`, diekspor dan dipakai untuk membungkus seluruh mux di `internal/panel/panel.go` `uiHandler`, sehingga `/agent/*` ikut terlindungi; `noFraming` bisa dihapus):

```go
// SecurityHeaders sets the baseline security headers on every UI and
// agent-bootstrap response. Handlers may override Cache-Control (static
// assets, SSE) after it.
func SecurityHeaders(next http.Handler) http.Handler {
	const csp = "default-src 'self'; script-src 'self'; style-src 'self'; " +
		"img-src 'self' data:; connect-src 'self'; object-src 'none'; " +
		"frame-ancestors 'none'; base-uri 'none'; form-action 'self'"
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		h := w.Header()
		h.Set("Content-Security-Policy", csp)
		h.Set("X-Content-Type-Options", "nosniff")
		h.Set("X-Frame-Options", "DENY")
		h.Set("Referrer-Policy", "no-referrer")
		h.Set("Permissions-Policy", "camera=(), microphone=(), geolocation=(), payment=(), usb=(), interest-cohort=()")
		h.Set("Cross-Origin-Opener-Policy", "same-origin")
		h.Set("Cross-Origin-Resource-Policy", "same-origin")
		h.Set("Cache-Control", "no-store") // cacheFor and the SSE broker replace it
		if r.TLS != nil {
			h.Set("Strict-Transport-Security", "max-age=31536000")
		}
		next.ServeHTTP(w, r)
	})
}
```

Pemakaian: di `uiHandler`, `return web.SecurityHeaders(mux)`. `cacheFor` (static) menimpa `Cache-Control` dengan `public, max-age=3600` dan broker SSE dengan `no-cache`; keduanya memang diinginkan. Temuan terkait: **SEC-08 (Sedang)**.

## 6. Rekomendasi penguatan untuk Rencana 2

1. **Bootstrap terverifikasi** (sudah dijadwalkan): perintah pairing memuat `sha256` skrip dan binary serta `--ca-sha256`. Selain itu: token lewat stdin/env, bukan argv (SEC-02); token terikat pada satu unduhan skrip (skrip membawa nonce sekali pakai untuk binary); `CheckRedirect` menolak redirect; UI menampilkan IP dan waktu pairing dan memberi peringatan bila IP-nya tidak sama dengan IP pengunduh skrip.
2. **Enkripsi rahasia di DB:** password user replikasi, token bot Telegram, dan password root MySQL lama dienkripsi dengan AES-256-GCM memakai kunci `/etc/dbpanel/panel.key` (0600, dibuat dengan `O_EXCL`, di luar `panel.db`, tidak ikut backup DB biasa), dengan nonce acak per nilai dan AAD = tabel+kolom+id. Token pairing disimpan sebagai hash (SEC-13). `mysql_root_password` di `agent.yaml` sebaiknya dihindari (pakai `auth_socket`); bila terpaksa, simpan di berkas terpisah 0600 dan jangan pernah kirim balik ke panel.
3. **Hardening systemd:** panel non-root dengan opsi di SEC-06; agent tertanam dipisah menjadi service root. Untuk agent: `UMask=0077`, `ProtectClock`, `ProtectKernelModules`, `ProtectHostname`, `RestrictSUIDSGID`, `LockPersonality`, `RestrictRealtime`, `SystemCallArchitectures=native`. Ingat bahwa ini tidak menahan agent yang bisa memanggil `systemctl`.
4. **Batas blast radius agent** (SEC-22):
   - registry per perintah dengan skema parameter yang ketat (enum peran, port 1–65535, host = IP/hostname tervalidasi, nama user `^[a-z_][a-z0-9_]{0,31}$`); tidak pernah ada perintah generik "tulis berkas", "jalankan", atau "unduh URL";
   - kebijakan lokal agent di `/etc/dbpanel/agent-policy.yaml` (milik root DB host, tidak bisa diubah panel) yang bisa menonaktifkan perintah berbahaya per server, mis. melarang `mysql.resetReplica`/`promote` di master produksi;
   - pembaruan binary agent hanya menerima binary yang ditandatangani **kunci rilis** yang dipin di binary, bukan kunci yang ada di panel (SEC-07), sehingga panel yang dibobol tidak bisa mendorong kode arbitrer;
   - konfirmasi dua langkah di UI untuk perintah destruktif, dan agent menolak perintah destruktif tanpa token konfirmasi yang dibuat sesaat sebelumnya;
   - batas konkurensi perintah di agent (`session.go:96`) dan satu job destruktif per server pada satu waktu;
   - agent mencatat setiap perintah yang diterima (nama, parameter disensor, hasil) ke journald lokal, jadi jejak tetap ada walaupun panel dibobol.
5. **Audit log** (SEC-17): tabel append-only, ditampilkan di UI, diekspor ke syslog; mencakup login, perubahan token/pairing, setiap perintah agent, dan perubahan pengaturan.
6. **Sesi dan autentikasi:** epoch kredensial, umur absolut, ganti sandi, logout semua sesi (SEC-04, SEC-15); semaphore bcrypt dan limiter global (SEC-05); allowlist Host (SEC-14).
7. **Validasi data agent** (SEC-11) dan batas ukuran pesan per jenis perintah; laju koneksi ulang per server.
8. **CI keamanan:** `govulncheck` dengan toolchain build, `go vet`, `staticcheck`, `shellcheck` wajib (sekarang dilewati bila tidak terpasang, `install_test.sh:62-68`), dan test regresi untuk SEC-03, SEC-04, dan SEC-09.
